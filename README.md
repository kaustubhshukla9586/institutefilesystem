# Privacy-Aware RAG System for Sensitive Institutional Documents

Project RK3P25KZB16. A question-answering assistant over the (fictional) documents of Thornwick University.
Personal data is redacted before anything is stored, retrieval is filtered by the user's role inside the
vector-database query, every answer is written by a Groq-hosted LLM from allowed documents only, and every
query is audited. All documents and people are synthetic.

**Stack:** FastAPI · SQLite (SQLAlchemy) · ChromaDB · Presidio + spaCy · sentence-transformers (all-MiniLM-L6-v2) · Groq (`openai/gpt-oss-20b`) · JWT + bcrypt · React (Vite) + Tailwind.

## Setup (Windows, Python 3.11+ and Node 20+)

```powershell
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m spacy download en_core_web_lg
copy .env.example .env      # then edit .env
```

### `backend/.env`

| Variable | Required | Meaning |
|---|---|---|
| `GROQ_API_KEY` | yes | Groq key; every answer is generated by the LLM |
| `JWT_SECRET` | yes outside dev | HS256 signing secret. The app refuses to start without it unless `APP_ENV=dev` |
| `APP_ENV` | no (`dev`) | anything other than `dev` makes `JWT_SECRET` mandatory |
| `CORS_ORIGINS` | no | allowed browser origin(s), default `http://localhost:5173` |
| `GROQ_MODEL` | no | default `openai/gpt-oss-20b` |
| `RELEVANCE_THRESHOLD` | no | cosine-distance cut-off, default `0.50` (calibrated, see DECISIONS.md) |
| `SQLITE_PATH` | no | default `backend/rag.db` |

## Ingest the documents

```powershell
cd backend
python -m app.ingestion        # redact -> chunk 500/50 -> embed -> ChromaDB (65 docs, 337 chunks)
```

## Run

```powershell
# terminal 1
cd backend; .venv\Scripts\activate; uvicorn app.main:app --port 8000
# terminal 2
cd frontend; npm install; npm run dev          # http://localhost:5173
```

API docs: http://localhost:8000/docs

## Tests and evaluation

```powershell
cd backend
python -m pytest -q tests          # 12 tests: access control, sign-up, 403s, features (no LLM calls)
python -m scripts.spec_check       # report claims S-1..S-8, PASS/FAIL
python -m eval.run_eval --calibrate   # distances only, no LLM
python -m eval.run_eval            # leak scan + 60-case role matrix + recall@k
```

Results go to `backend/eval/results/results.md` and `eval_results.json`. Groq answers are cached in
`answer_cache.json`, so a rerun with unchanged chunks costs no API calls. Latest run: **leaks 0**,
role matrix **57/60** (all three failures are over-cautious refusals of allowed questions; no restricted data
was shown), recall@1 **0.95**, recall@3 **1.0**, recall@5 **1.0**.

Frontend e2e (needs the backend on :8000 and `npm run build && npx vite preview --port 5173`):

```powershell
cd frontend; npx playwright test   # verifies roles, 403 page, axe, mobile; writes ../screenshots
```

## API

| Method | Path | Who | Purpose |
|---|---|---|---|
| POST | `/auth/signup` | anyone | create a student account |
| POST | `/auth/login` | anyone | JWT (60 min); 5 failures / 5 min -> 429 |
| GET | `/me` | signed in | email, role, allowed levels |
| POST | `/query` | signed in | `{answer, refused, sources:[{doc_id,title,access_level,snippet}]}` |
| GET | `/my-stats` | signed in | own counters for dashboards |
| GET | `/documents` | signed in | documents at or below your level |
| GET | `/documents/{id}?view=redacted\|raw` | admin | stored vs original; `raw` is logged as a `reveal` |
| POST | `/documents/upload` | faculty, admin | .txt/.md/.pdf with an access level up to your own |
| GET | `/audit-log?role=&user=&q=&result=&event=&from=&to=&page=` | admin | filtered audit log |
| GET | `/stats` | admin | admin dashboard counters |
